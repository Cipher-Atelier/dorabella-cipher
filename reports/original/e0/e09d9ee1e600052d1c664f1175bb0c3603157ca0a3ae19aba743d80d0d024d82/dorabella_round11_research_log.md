## 2. Точное семейство

Знак `g=3*o+c`, направление `o=0..7`, число дуг минус один `c=0..2`. Алфавит:

```text
A24 = ABCDEFGHIKLMNOPQRSTUWXYZ
ABC / DEF / GHI / KLM / NOP / QRS / TUW / XYZ
```

Объединены I/J и U/V. Допустимы произвольная перестановка P восьми **сохранённых** троек, общий выбор средней позиции `m`, и независимый бит разворота `b[o]` для каждого направления:

```text
Q0 = [1,0,2]
Q1 = [0,1,2]
Q2 = [0,2,1]
R_b(c) = 2-c при b=1, иначе c
key[3*o+c] = A24[3*P[o] + Qm[R_b[o](c)]]
```

Полное число разных ключей:

`8! × 3 × 2^8 = 30 965 760`.

Канонический номер — `768*lex_rank(P) + 256*m + mask`; младший бит mask относится к направлению 0. Все таблицы взаимно однозначны. Из полной таблицы однозначно восстанавливаются P (номер тройки), m (место при двух дугах) и биты разворотов (порядок двух крайних рангов). Это доказывает отсутствие дубликатов. Вариант `8!*6*256` учитывал бы каждый ключ дважды: общий разворот и одновременное инвертирование всех битов дают ту же таблицу.

Семейство содержит прежние **241 920** ключей round10 при mask=0 или mask=255. Включение проверено программно. Оно в 128 раз шире round10, но **не** является всеми подстановками, всеми разбиениями букв или всеми независимыми перестановками троек. Место средней буквы здесь всё ещё общее для всех направлений.

Сохранены оба исходных чтения Hauer/Hartmeier, все 87 знаков и их порядок. Точки не объявлялись командами; знаки, дуги и направления не исправлялись. Печатные границы строк не меняют состояние. Тетрадные тройки — историческая опора предыдущих раундов; именно это расширение — проверяемая гипотеза, не новый найденный ключ автора.

**Основной ключ выбирается исключительно по первым 43 знакам.** Файл `data/search_inputs.json` содержит только эти префиксы и идентификаторы, не содержит суффиксов, истинных текстов или ключей. Функция поиска не получает последние 44 знака. После окончательного выбора ключа суффикс отдельно декодируется и оценивается; используются только его внутренние 4-граммы, без окон через разрез. В этом раунде не выполняется новый подбор ключа по всем 87 знакам.

Правило ничьей: наибольший float64 S43; при **точно равных** значениях — наименьший канонический ID. Все точные равные максимумы сохраняются. Допуск 1e-10 используется только при описательном сравнении контрольных баллов, не для выбора ключа. Истинный ответ и test при разрешении ничьих не используются.

Это машинный holdout по входу декодера. Он не превращает давно виденную вторую половину исторической Dorabella или старые контрольные письма в новый независимый исторический материал.

## 4. Почему максимум точный, хотя не у всех ключей считался W

Для каждого P,m, неизвестный бит разворота позволяет крайним дугам читать одну из двух букв, а средней — одну. В верхней оценке словарный алгоритм разрешает выбирать любую из этих букв **независимо на каждом вхождении**. Это более свободная модель, чем единая таблица: все 256 настоящих масок в неё включены, но разрешены и противоречивые сочетания. Поэтому `W_upper >= W` для любого из 256 ключей.

Символьный балл C рассчитан для каждого ключа. Точный W можно пропустить только при `C+0.5*W_upper < уже найденный S43 - 1e-9`. Запас 1e-9 консервативен относительно округления. Нет top-K, стохастического отбора или остановки по удачному результату. Это точное отсечение по верхней границе, а не эвристическое отбрасывание.

Основная серия содержит **2 910 781 440** символьных оцениваний «ключ–вход» (94×30 965 760). Точный W потребовался для **80 553** пар, остальные словарные вычисления безопасно отсечены. Не утверждается, что основная серия вычислила оба компонента на всех 2,9 млрд пар или что это 2,9 млрд независимых гипотез.

Дополнительно на шести входах действительно вычислены **оба компонента на каждом ключе**, всего **185 794 560** полных оцениваний, без отсечения. Максимумы, выбранные номера и **все точные ничьи** совпали. Эти шесть входов выбраны для проверки реализации после основных результатов. Это отдельный вычислительный аудит, не новые независимые текстовые данные и не изменение основного протокола.

## 7. Исполнение, checkpoints и проверки

Основные 94 входа закончены: 12+2 положительных/регрессионных, две транскрипции, 78 отрицательных. На каждый — 40 атомарных checkpoints по 1024 P (последний меньше), всего **3760** блоков. Они хранят границы диапазонов, входящий/выходящий максимум и ничьи, upper bounds, числа вычислений, все фактически вычисленные C/W, SHA-256 массивов и файлов.

Проверены цепочки всех блоков и все 94 результата. Все **80 553** сохранённые символьные оценки пересчитаны независимой векторизованной формулой; для детерминированных выборок в каждом блоке и итоговых ключей использован независимый Python-словарный DP. Максимальное расхождение составило **6.217248937900877e-15**. Все 87 знаков каждого входа восстанавливаются обратной таблицей; это внутренняя согласованность кандидатов, не историческая правильность.

Полностью повторены семь основных поисков (не только оценка выбранного ключа): `bailey_01`, `bailey_08`, `elgar_march_1897`, обе реальные версии и первый отрицательный контроль каждой. На каждом совпали все 40 наборов массивов checkpoints побитно, максимумы и ничьи.

Шесть дополнительных полных неотсечённых проверок: `bailey_05`, старая открытка, обе реальные версии и первые два отрицательных контроля. Каждая рассматривает 30 965 760 ключей с полным C и W. Все совпали. Для малых выборок блоков также выполнены прямые независимые сравнения и проверки верхних границ.

Генерация всех 14 новых шифрований и 78 отрицательных последовательностей повторена по seeds. В каждой отрицательной выборке 39 разных строк. Первоначальный архив round10 и его 7500 файлов неизменны. Старые неархивированные исследования не стали подтверждёнными от присутствия в старых заметках.

### Реальная техническая остановка

Один вызов дополнительного неотсечённого аудита завершился лимитом инструмента. Последующая проверка процессов показала, что runner уже не работает. К тому моменту четыре случая были закончены, у двух осталось 32 и 31 из 40 готовых блоков. **Без изменения численного кода** работа продолжена с этих checkpoints; все шесть в итоге закончены. Записанные блоки не выдавались за полный результат до завершения. Главная серия 94 к этому моменту уже была закончена и проверена.

Логи первоначального и возобновлённого запусков сохранены раздельно; `logs/technical_events.json` фиксирует остановку. Действующий процесс не дублировался и не завершался вручную. Никакой обещанной работы в фоне нет.
