# Dorabella — раунд 3: проверка слов и независимые контрольные письма

Дата: 25 сентября 2026 года. **Расшифровка не получена. Новый механизм шифрования не установлен.**

Этот раунд продолжает воспроизводимую лабораторию из архивов первого и второго раунда. Его новые результаты относятся к конкретной реализации и ограниченному семейству автоматов, а не ко всем способам шифрования. Они не устанавливают научную новизну геометрических наблюдений.

## 1. Главный результат

Удалось исправить конкретную ошибку ранжирования: первый трудный разработческий пример Стивенсона теперь восстановлен полностью, вместо 44,83% букв. На восьми старых примерах доля результатов с ≥90% букв выросла с 5/8 до 7/8; средняя точность — с 85,34% до 93,39%. **Это настройка на уже знакомых примерах, не независимая проверка.**

На 12 новых отрывках из отдельных писем Чарлза Лэма средняя точность выросла с 89,56% до 92,34%. Доля примеров с ≥90% правильных букв осталась 10/12. Полностью восстановлено 7/12 вместо 4/12. Один тяжёлый сбой остался на уровне 25,29%. Следовательно, улучшилась точность, но на этой небольшой выборке не выросло число случаев, прошедших заранее использованный порог 90%.

Dorabella не превратилась в связный текст. На 39 новых контрольных перестановках один контроль обогнал её по лучшему итоговому баллу. Прибавка от поиска автоматов оказалась не больше, чем у 37 из 39 контролей. Поддержки конкретному механизму по этому показателю не получено.

## 2. Что изменено и что НЕ изменено

Сохранены транскрипция 87 знаков, порядок чтения и семейство 672 двухсостоянийных автоматов из предыдущего раунда. Все они меняют только бинарную полярность, оставляя ось и число дуг без изменений. На Dorabella остаётся 207 различных схем повторений. Строки объединены без сбросов состояния, точки не используются. Нового визуального аннотирования рукописи не проводилось.

Первичный поиск **полностью тот же**, что в `scan_v2.py`: новостная условная символьная 4-граммная модель, этапы 8×16000, 32×20000 и 128×20000, отбор 32 и затем 8 схем. Для каждой схемы прежний движок сохраняет один лучший ключ по старому критерию.

Новый этап получает восемь лучших сохранённых кандидатов и исходную последовательность без автомата, если она не вошла в восьмёрку. Каждому кандидату разрешены до 30 шагов жадного улучшения: перебор перестановок двух букв, затем выбор наибольшего улучшения. Изменяется только взаимно однозначная таблица букв, не шифрознаки и не число позиций.

Новая функция:

```text
S = C + 0.5 × W
C = средний ln P(буква | три предыдущие буквы), старая модель
W = лучший суммарный логарифмический словарный балл сегментации / 87
```

Это комбинированный эвристический балл, **не вероятность правильности сообщения**. Нельзя напрямую сравнивать новый S со старыми баллами C.

## 3. Словарь и сегментация

Использован предсуществующий частотный словарь `textblob/en/en-spelling.txt` из TextBlob 0.19.0. После удаления не-ASCII-слов и одиночных букв, кроме `a` и `i`, осталось **29 133 словарных формы**, сумма частот — **1 096 363**.

SHA-256 словарного файла:

```text
eade91558167fe09a481abf59e176af8643ad78678cc53dd5aeaf2a8b30fa332
```

Заголовок источника сообщает о книгах Project Gutenberg и частотных списках Wiktionary/British National Corpus, но не даёт точного перечня исходных документов. **Нельзя удостоверить отсутствие этих авторов в исходных данных чужого словаря.** Сам словарь содержит отдельные слова и частоты, а не последовательности наших тестовых писем. Тестовые фрагменты не добавлялись в словарь и не использовались для переобучения.

Динамическая программа ищет сегментацию с максимальной суммой `ln(count(word)/total)`. Максимальная длина слова — 24. Неизвестная буква получает штраф −8. Для обрезанных слов на начале и конце 87-буквенного фрагмента используются суммы частот подходящих суффиксов/префиксов с дополнительным штрафом −2. Одиночные неизвестные буквы и обрезанные слова явно отмечаются в диагностическом выводе. Эти пробелы — результат модели, не данные рукописи.

**Проверяются отдельные слова, но не грамматика и смысл.** Случайная последовательность коротких настоящих слов также может получать хороший балл.

Полные тома исторических писем не были загружены в вычислительную среду: прямое скачивание не сработало. Поэтому здесь **нет новой языковой модели, обученной на большом историческом корпусе**. Вместо неё реализован отдельный словарный критерий. Отрывки для теста перенесены из видимого текста первичного источника, их происхождение сохранено.

## 4. Настройка и фиксация протокола

Сначала на восьми прежних примерах проверено чистое перераспределение мест в готовой восьмёрке кандидатов; затем — локальное уточнение ключа. Для комбинированного критерия испытаны коэффициенты 0.25, 0.5, 1, 2 и 4. Значение 0.5 выбрано по числу примеров с ≥90% букв, затем по средней точности, затем по меньшему коэффициенту при равенстве. Пробные таблицы сохранены, включая менее удачные варианты.

После этого исходники, старая модель, словарь и параметры зафиксированы хешами в `results/v3/frozen_protocol.json`. Только затем созданы и расшифрованы 12 новых примеров. Новые примеры не использовались для изменения основного протокола v3.

Это фиксация текущей процедуры, **не предварительная регистрация всей гипотезы Dorabella**. Семейство, геометрические признаки и направление исследований выбирались по этому шифру в прошлых раундах.

## 5. Новые исторические примеры

Источник: *The Best Letters of Charles Lamb*, Project Gutenberg №10125. Использованы начала 12 разных писем, после удаления обращения — первые 87 ASCII-букв. Это удобная выборка из фрагментов, видимых при поиске по источнику, **не случайная и не репрезентативная выборка всей переписки XIX века**.

Начальные строки в полученном текстовом представлении: 895, 3004, 3034, 3065, 3125, 3325, 3524, 3653, 4128, 4322, 4370, 4592. Исходные написания, включая `mariner` и `tetter`, сохранены. Извлечённые фрагменты, координаты, хеши и шифрознаки находятся в `results/v3/heldout/inputs.json`.

Фрагменты отсутствуют как целые строки в обучающем новостном корпусе. Известный нетривиальный автомат и случайная подстановка выбраны генератором с seed 2026092503. Сначала программа получает только шифрознаки; правильный текст используется исключительно после выбора результата для измерения точности.

| Показатель на одинаковых 12 новых шифрах | v2 | v3 |
|---|---:|---:|
| Средняя точность | 89,56% | 92,34% |
| Восстановлено ≥90% букв | 10/12 | 10/12 |
| Восстановлено 100% букв | 4/12 | 7/12 |
| Минимальная точность | 25,29% | 25,29% |

Нельзя приписывать рост точности только одному фактору: v3 имеет и другой критерий, и дополнительные локальные шаги. Новость здесь — результат фиксированной процедуры на новых примерах, не доказательство превосходства при одинаковом бюджете.

## 6. Конкретная старая ошибка ранжирования

Для `history_00` прежний победитель содержал только 44,83% правильных букв. По старой оценке C он обгонял настоящий текст:

| Текст | Старый C | Новый S |
|---|---:|---:|
| Истинный текст | −2,573862 | **−3,620843** |
| Старый ложный победитель | **−2,427364** | −4,244282 |

Новая слепая процедура, не получая правильный автомат или текст, выбирает и восстанавливает истинный 87-буквенный фрагмент целиком. Это регрессионный тест на известной разработчикам ошибке, не независимый научный результат.

## 7. Dorabella и контрольные перестановки

### Основной новый контроль

Заранее выбраны 39 новых полных перестановок шифрознаков с seed 2026092504. Число 39 фиксировано перед запуском; остановки по уровню значимости не было. На каждом примере **заново** выполнен весь неизменённый поиск v2 и новый этап v3. Сохраняются точные частоты полных знаков; связи между соседями разрушаются.

| Показатель S | Dorabella | Среднее 39 контролей | Контролей не хуже |
|---|---:|---:|---:|
| Без автомата, с подбором букв | −4,594508 | −5,087335 | 0/39 |
| Лучший по всему поиску | −4,478387 | −4,689753 | 1/39 |
| Прибавка от автоматов | +0,116120 | +0,397583 | 37/39 |

Описательные перестановочные хвостовые оценки по правилу `(k+1)/(n+1)`: 0.025, 0.05 и 0.95. При 39 контролях разрешение грубое. Это **не вероятность правильности автомата и не вероятность того, что текст случаен**. История выбора семейства и критериев всё ещё делает анализ поисковым.

Исходный порядок шифра отличается от перемешиваний в рамках нашего критерия. Но поиск автоматов сильнее улучшает случайные контроли, чем Dorabella. Убедительного дополнительного свидетельства механизму не получено.

### Повторное использование прошлых 99 контролей

На всех 99 сохранённых банках кандидатов v2 отдельно заново выполнен v3. Сам неизменённый поиск v2 здесь **не пересчитывался**, поскольку его результаты уже сохранены; это корректное повторное использование детерминированного промежуточного результата, но не новая независимая выборка.

Из 99 контролей лучший S Dorabella не превзошёл ни один; её прибавку превзошли или сравняли 94. Эти числа не заменяют основной новый контроль и не обосновывают выбор более выгодного p. Две выборки не объединены для получения более красивого показателя.

### Что выдал лучший вариант

Полный текст и правило находятся в `results/v3/cached/dorabella.json`. Он не образует связного сообщения. Диагностические пробелы и короткие словарные совпадения не считаются расшифровкой. Ни одна буква Dorabella не объявляется установленной.

## 8. Почему остаются ошибки

У обоих новых примеров ниже 90% правильная схема повторений дошла до финального поиска. Проблема не в её удалении на раннем этапе. Но один сохранённый ключ для этой схемы оказывается недостаточен.

Отдельная диагностика дала поиску известный правильный автомат, но не буквы. В `lamb_06` новый случайный запуск и словарное уточнение восстановили 100% текста; в основном слепом результате осталось 25,29%. В `lamb_07` такой диагностический запуск дал лишь 87,36%, а истинный текст имел заметно лучший достижимый балл.

Для старого `history_03` диагностика с правильным автоматом также дошла до 100%, хотя основной v3 дал 51,72%. Эти запуски **не засчитываются** в слепые показатели.

Важно: они **не доказывают**, что основной поиск уже находил и затем выбросил истинный ключ. Они показывают, что хороший ключ существует и может быть найден при другом запуске, а в итоговом банке его нет. Архитектурное ограничение подтверждено кодом: на схему хранится один победитель по старому критерию до применения нового.

### Дополнительный неудачный эксперимент с пулом ключей

После основной проверки выполнен один диагностический эксперимент на `history_03`: по 64 перезапуска для каждого из девяти финалистов, с сохранением лучшего ключа **каждого** перезапуска. Получено **575 разных выводов** по финалистам (дедупликация внутри каждой схемы). К каждому применён новый словарный этап.

Правильный автомат не подсказывался, однако пример уже был известен при разработке этой диагностики. Лучший результат остался на **66,67%** букв. Поэтому простое увеличение пула в этой конфигурации ещё не решило проблему; скрывать этот отрицательный результат или обещать успех от сохранения вариантов было бы неправильно.

Полный пул сохранён в `results/v3/keypool_diagnostic.json`. Это не модификация зафиксированного v3 и не часть независимой оценки 12 писем.

## 9. Технические проверки

- На 200 случайных строках Python- и Numba-реализации словарного балла дали одинаковые значения; максимальная ошибка 0.
- На 30 случайных примерах проверены монотонность локального улучшения, перестановочность ключа и сохранение схемы повторений.
- Все 12 известных шифров прошли проверку обратного преобразования.
- Проверены 453 повторных шифрования кандидатных текстов из новых положительных и отрицательных примеров: восстановлены исходные знаки.
- Dorabella полностью пересчитана неизменённым v2, а затем v3; текст и баллы совпали с сохранёнными результатами.
- Хеши всех зафиксированных исходников, модели и словаря совпали.

Результаты: `results/v3/implementation_checks.json`. Сводная таблица содержит **159 строк**: 8 разработческих, 12 новых положительных, Dorabella и 99 переиспользованных отрицательных, 39 новых отрицательных. Диагностика с подсказками и эксперимент с пулом учитываются отдельно.

## 10. Воспроизведение

Среда: Python 3.13.5. Зависимости закреплены в `requirements_round3.txt`. Исходная символьная модель включена в архив; словарь берётся из установленного TextBlob 0.19.0, его хеш проверяется. Полные Gutenberg-тома для расчётов не нужны: использованные короткие исходные отрывки сохранены.

```bash
pip install -r requirements_round3.txt
python wordscore_v3.py
python wordpolish_v3.py
python scan_v3.py
python validate_v3.py
python cached_v3.py
python fresh_controls_v3.py
python diagnose_v3.py
python keypool_diagnostic_v3.py
python checks_v3.py
python report_v3.py
```

`validate_v3.py`, `cached_v3.py` и `fresh_controls_v3.py` используют готовые соответствующие результаты, если файлы существуют. Для чистого повторения сначала сохраните результаты и удалите папки `results/v3/heldout`, `results/v3/cached`, `results/v3/fresh_null`. Не смешивайте результаты изменённого кода с зафиксированным протоколом. `checks_v3.py` в любом случае заново запускает полный поиск на Dorabella.
