# TS-TRANSPORT-PROFILE-v1 — до исполнения

Статус: PREPARED_NOT_EXECUTED_AWAITING_APPROVAL. Это новая версия транспорта и отдельный load-only профиль. Прежний PASS_FINITE_DIFFERENTIAL_ONLY, Storage-v2, adapter-v2 и TS-RC-v2 OOM неизменны. Новый код не импортирован и не запущен, включая Perl compile-only. Единственное выполненное действие с данными — заранее ограниченный собственный подсчёт сохранённых списков и старого профиля (SIZING_*).

## Установленное основание

Сохранённый список `abcdefgh` содержит 63 911 кандидатов: старый JSON-ответ занимает 703 027 байт, превышая cap 65 536. Это прямой correctness blocker старого транспорта. Источник: `evidence/real_lists.json`, SHA256 002ed437c9636553ad39f45b90405b56c5c463217cf70af7923cf0c8c2e457a7; полный Storage-v2 удостоверил глобальные maxlist=63911 и max_candidate_bytes=46. Собственный подсчёт завершился exit0 за 0.02337 s, maxRSS19 316 KiB; новой загрузки модели не было.

Новый протокол: `[seq,"begin",count]`, последовательные `[seq,"chunk",offset,values]` по 64 кандидата, `[seq,"end",count,payload_bytes]`. Не более 999 chunks. Для ASCII длиной ≤46 даже escape по 6 байт даёт кадр ≤`64*(46*6+3)+128=17984` байта. Ограничение кадра 65536 остаётся. При count=0 передаются begin/end; отсутствие списка — отдельный null. Получатель выдаёт весь массив только после проверенного end; EOF, неверные offset/count/байты, чужой seq или oversize означают STOP. Порядок и дубли сохраняются последовательной конкатенацией. Это аргумент для допустимых кадров; будущие fixtures дают только конечное свидетельство реализации.

Полный список всё равно существует в Python и Perl: streaming снимает монолитный JSON и ограничивает промежуточные кадры, но не устраняет массив результата. Проверенный `adapter.py` неизменён: readonly URI, SQL ORDER BY seq, order-1 словарь, cache2/8MiB payload, word-cache1024, SQLite4MiB/mmap0. Политика cache не меняет значения/порядок; размер Python-объектов не равен учтённому payload.

## Один staged attempt после отдельного согласия

Команда: pinned Python3.12.14 `-I -S run_staged.py` из данного пакета. Точные argv всех дочерних ролей образуются только в `child_gate.py`; FREEZE.json содержит пути, hashes, роли и окружение. Perl5.38.2/NVdouble8, LC_ALL=C, TZ=UTC, PERL_HASH_SEED=2026101705, PERL_PERTURB_KEYS=0. Установка, сеть в исполняемом коде, production entrypoint, 87-control и Dorabella отсутствуют. Ограничение сети обеспечивается отсутствием сетевых операций в проверенном scope, не новым сетевым sandbox.

**A — транспорт, ≤60 s от T0.** Два последовательных запуска пар broker+Perl, не более трёх процессов вместе с supervisor. (1) Неизменённый прежний `differential.pl`: те же 3 synthetic cases×2 MCTS, неизменные LM-fixtures, score/ties/hash-order. Требуется побайтовое равенство всей трассы сохранённой оригинальной reference: 300 events,64 score calls,6 iterations, все6-позиционные inverse; повторять оригинальный reference не требуется. (2) Транспорт сохранённых полных списков `a,aa,ab,aba,abc,abcdefgh,!,abcdefgh` с сопоставлением всех значений/дублей, caller mutation и повторным maxlist; 10 фиксированных malformed-frame отказов и один положительный split/duplicate. Это регрессия транспорта, не новая чувствительность solver.

**P — только условный load-only, ≤60 s включая его хеш-проверки.** Только после PASS_A и двух resource gates. Полностью сверить hashes шести исходных LM, исходного .patlst и уже verified SQLite; ничего не строить. По одному вызвать неизменные ReadLM::ReadUnigramLM/ReadBigramLM/ReadTrigramLM, удерживать все шесть hash-структур одновременно. Через readonly broker запросить те же восемь списков, затем шесть уже сохранённых segmentation-проб `to,togo,xxyyzz,catdog,""," \t "`; сравнить строки и полный порядок word membership запросов. Записать собственные VmPeak/VmSize/VmHWM/VmRSS после каждого LM и storage-пробы. **Ноль scoring/search calls, ноль входов длиной87.** Полные файлы проверяются hash до/после. Отказ resource gate — SKIPPED_RESOURCE, без ожидания освобождения памяти, повторов или очистки кеша.

## Бюджет и его пределы

| Компонент | Ограничение / установленное | Что не доказано |
|---|---|---|
| Perl A | AS128MiB, CPU20/22s | Суммарный RSS группы не равен ru_maxrss одного ребёнка |
| Perl P: все6 LM + полученные массивы + NoSpace | AS2GiB, CPU50/52s | Что любой полный поиск поместится; cap не обещает успешную загрузку |
| Python broker | AS128MiB, CPU20/22s; cache/SQLite описаны выше | Полный Python heap не ограничен одним payload cache |
| Supervisor/readback | AS128MiB, CPU170/175s | Внешняя остановка при гибели самого host не гарантирована |
| IPC | кадр≤65536; candidate payload≤2939906; request≤80000; chunks≤999/list | Perl array/SV и sort/search copies не равны payload |
| Общая среда | memory.max8GiB; активных детей≤2; каждый в доказанной своей process group | Другие процессы/файловый кеш не зарезервированы и могут расти |

Файлы P вместе занимают **1 241 208 851 байт**; это также консервативный учёт возможного нового файлового кеша при чтении. Сумма process-AS caps P=2.25GiB. Дополнительно заложены128MiB на IO/output/kernel и1GiB номинального свободного остатка. Поэтому P pre-hash current≤3.4GiB, post-hash current≤4.625GiB; сумма pre-hash + все входные байты + AS caps +128MiB <7GiB. Это admission policy, не доказанный верхний предел чужих kernel allocations. Не предполагается автоматическое вытеснение кеша. A admission≤6.5GiB; его сумма process caps384MiB+128MiB allowance даёт≤7GiB. Оба этапа прекращаются при наблюдаемом current≥7GiB. Poll50ms — не hard realtime и не гарантия против мгновенного внешнего всплеска.

При подготовке current=6 684 860 416 байт: **P не допускается**, A допускается по сохранённому снимку; перед запуском всё проверяется заново. Большие входы сейчас сверены по размеру и сохранённым идентичностям; свежий полный hash разрешён только внутри P после его pre-gate. Внешняя база и LM не включены в маленький ZIP и должны уже присутствовать по FREEZE; отсутствующий файл не восстанавливается исполнением/перестройкой.

Старый TS-RC-v2 после сообщения о завершении шести LM и переходе к .patlst имел VmPeak1 996 444KiB (~1.90GiB), RSS1 991 892KiB. Это измеренный максимум того префикса плюс часть .patlst, не прогноз полного поиска. P cap2GiB выбран ниже прежнего4GiB на этом основании; превышение остановит версию без повышения. Оригинальная .patlst-структура больше не строится. Search peak остаётся неизвестным: полные списки, сортировки перед pl50, candidate hashes, дерево MCTS, строки/ключи, scoring/segmentation temporaries. Нельзя вычитать их из размера файла или линейно экстраполировать старый OOM. Ни P PASS, ни запас AS после P не разрешают full87 автоматически.

## Остановка и исход

Один общий T0/180s включает проверки, A, условный P и readback. Внутри каждого60s этапа последние4s резервируются для остановки: рабочий tick срабатывает к56s (и не позже глобального deadline−4s). Дочерние stdin поискового ввода отсутствуют; IPC-пайпы только между своей парой. До release проверяются PID/NSpid/PGID/SID/starttime, принадлежность namespace, реальные RLIMIT. TERM, затем2s grace/KILL, затем2s наблюдение только доказанной своей группы; grace входит в итоговое время. Это внешний наблюдающий supervisor с OS AS/CPU limits, не новый cgroup и не обещание crash durability. При неизвестной принадлежности сигнал не адресуется наугад, исход UNKNOWN. Gate EOF до release даёт выход без Perl. Любой ненулевой exit/stderr, deadline, изменение hashes, malformed frame, новые OOM events или несовпадение → STOP; никакого retry/resume. Оставшаяся группа/неподтверждённое завершение → UNKNOWN. Запись T0 и артефактов локальная, result атомарно/fsync; потеря host остаётся UNKNOWN.

stdout/stderr, raw IPC, observations, phase exits, группы, readback и hashes сохраняются. Cap8MiB/file и64MiB output суммарно; это дополнительные причины STOP, не усечение ради PASS. Финальный PASS_A_PROFILE_SKIPPED_RESOURCE означает только A; PASS_TRANSPORT_AND_LOAD_PROFILE_ONLY означает A+P. Требуются exit0 и пустые группы. После любого исхода — readback, без следующего автоматического этапа.

**Запрос владельцу:** разрешить ровно один `TS-TRANSPORT-PROFILE-v1`: этап A и, только при PASS_A и зафиксированном resource gate, этап P без поискового входа. До180s всего, максимум3 процесса, AS128MiB у малых процессов и2GiB только у Perl P, без сети/установок. Пакет содержит новый изменённый glue. Полный solver, технический87-control и Dorabella не входят в согласие.
