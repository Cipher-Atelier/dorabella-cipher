# Dorabella: воспроизводимый исследовательский раунд

Дата: 25 сентября 2026 года. Статус: **расшифровка не получена; нового механизма не установлено**.

Это журнал вычислений данного раунда. Он не удостоверяет вычисления, упомянутые в более ранних сообщениях без сохранённого кода. Прежние языковые оценки вроде −7.97 не сопоставимы с моделью и единицами измерения ниже.

## 1. Данные и ограничения транскрипции

87 токенов вручную перенесены из Figure 2 статьи Hauer et al., *Dorabella Cipher as Musical Inspiration*, SMP 2021, страница 34. Таблица сверена с изображением PDF. Использованы напечатанные строки длиной 29, 31 и 27 токенов. Основной анализ объединяет их слева направо, без сбросов состояния на границах строк и без операций по точкам.

Файл: `data/dorabella_smp2021.txt`. Ориентации A–H обозначаются числами 0–7, число дуг — 1–3. Противоположные пары в используемой геометрической конвенции: A/E, B/F, C/G, D/H. Это **не новая независимая слепая разметка рукописи**; неоднозначность отдельных нарисованных знаков остаётся ограничением.

Параметры знака в программах:

```text
orientation = 0..7
arcs_zero_based = 0..2
axis = orientation % 4
polarity = orientation // 4
base = 3 * axis + arcs_zero_based
```

Последняя формула даёт ровно 12 возможных базовых классов. Формула с множителем 4 перед axis для такой нумерации неверна.

## 3. Перестановочные проверки

В таблице p вычислено как `(число превышений + 1) / (число симуляций + 1)`. Это хвостовая вероятность при конкретной модели сравнения, а не вероятность того, что шифр случаен, и не вероятность истинности гипотезы.

| Проверка | Превышения | Число симуляций | p с поправкой +1 |
|---|---:|---:|---:|
| Перемешать порядок; фиксировать физические оси; получить ≥41 | 15 | 200000 | 0.0000800 |
| Перемешать порядок; разрешить лучшее из 105 разбиений; получить ≥41 | 528 | 200000 | 0.0026450 |
| Перемешивать оси только внутри групп одинакового числа дуг; получить ≥41 | 8 | 200000 | 0.0000450 |
| Перемешивать полярности внутри каждого базового класса; получить ≥27 разворотов | 2995 | 200000 | 0.0149799 |
| То же; получить ≥13 точных зеркальных пар | 4837 | 200000 | 0.0241899 |

Первый и второй тесты отвечают на разные вопросы. Второй учитывает только поиск среди 105 разбиений, **не всю историю выбора гипотез и статистик**. Все выводы о Dorabella остаются поисковыми, а не результатом независимой предварительной регистрации.

Условное перемешивание полярности сохраняет весь порядок базовых знаков и частоты полных знаков. Поэтому оно отделяет структуру бинарного компонента от уже установленной структуры осей.

Дополнительно выполнено 1000000 случайных переназначений полных знаков 24 геометрическим формам. Для ≥41 сохранения оси найдено 8 превышений; для взаимной информации ≥0.322197 — 12476. Совместного превышения двух порогов не было. Это описательная проверка выбранной модели случайной разметки алфавита, **не универсальное p-value и не доказательство расшифровки**. Полные числа и биномиальные интервалы сохранены в `results/audit.json`; выборки — в `results/audit_null_arrays.npz`.

## 4. Почему 12 × 2 само по себе не означает память

Запись 24 знаков как 12 базовых форм и одного бита — переобозначение алфавита. Если каждой паре `(base, polarity)` навсегда соответствует одна буква, это всё ещё обычная фиксированная подстановка. Для модели с памятью требуется дополнительная зависимость от истории.

Все исследованные ниже преобразования меняют только полярность. Поэтому они **тождественно сохраняют последовательность осей и числа дуг**, включая 41 сохранение оси. Эта геометрическая аномалия не может сама по себе служить доказательством конкретного переключателя полярности.

## 5. Проверенное семейство автоматов

Состояний ровно два: 0 и 1. Выходная полярность равна входной полярности XOR текущего состояния. Следующее состояние определяется произвольной двоичной таблицей от текущего состояния и одного выбранного входа: полярности, числа дуг либо оси текущего шифрознака. Оба начальных состояния проверены.

Число определений:

```text
2 * (2^(2*2) + 2^(2*3) + 2^(2*4)) = 672
```

На Dorabella после удаления эквивалентных схем повторения символов остаётся 207 вариантов. Проверены все 672 определения, но это **не все возможные автоматы с двумя, тремя или четырьмя состояниями**. Отдельно для каждого определения проверена обратимость преобразования.

Для оценки использована собственная условная символьная 4-граммная модель английского языка, обученная на 300 новостных документах `lee_background.cor` из Gensim: 289698 букв после нормализации. Это небольшой современный корпус, не переписка Элгара. Не использовались предполагаемые расшифровки, имена, дата письма либо подсказки о словах.

Для каждой отличающейся схемы повторений: 2 начальных запуска по 4000 шагов. Затем три лучших кандидата и исходный вариант без преобразования получают до 128 запусков по 20000 шагов. Бюджет задан на кандидата; эквивалентные схемы не получают дополнительных запусков. Случайные начальные состояния оптимизатора детерминированы хешем входной последовательности и этапа поиска.

Та же процедура целиком повторена для **99 случайных перестановок полных знаков**, сохраняющих их частоты. Это существенно: сравнивается лучший результат всего поиска с лучшим результатом такого же поиска, а не с одним случайным ключом.

## 6. Результат языкового поиска

Оценка — средний натуральный логарифм условной вероятности следующей буквы по 84 четырёхбуквенным окнам. Больше, то есть ближе к нулю, означает лучше только в рамках этой модели.

| Показатель | Dorabella | Среднее по 99 контролям | Контролей не хуже |
|---|---:|---:|---:|
| Без автомата, с подбором подстановки | −2.736934 | −2.977418 | 0 |
| Лучший вариант всего поиска | −2.686180 | −2.834278 | 3 |
| Прибавка относительно исходного варианта | +0.050754 | +0.143140 | 83 |

Соответствующие p с поправкой +1: 0.01, 0.04 и 0.84. Из-за размера контрольной выборки эти величины имеют грубое разрешение; ноль превышений не означает нулевую вероятность.

Основной вывод: исходный порядок Dorabella отличается от перемешиваний по данной оценке, но **именно выигрыш от добавления автомата не выделяется**. Он даже меньше типичного выигрыша на контролях. Это не доказывает, что исходный текст английский, и не исключает другие алгоритмы шифрования.

Лучший найденный вывод не образует связного сообщения:

```text
WYERUTDROPIENCEMEETYRECOGOAVIDEDTOROGYSEESTANDEVETHINCOLLOVISITHISCHKAISETHNIARRAITRNOR
```

Этот текст — результат оптимизации, не предлагаемая расшифровка. Таблица лучшего автомата и все контрольные результаты записаны в `results/scan_summary.json` и `results/scan_records.jsonl`.

## 7. Проверка чувствительности и найденное узкое место

Для выбора достаточного бюджета подстановочного поиска использованы 20 фрагментов по 87 букв из отдельного файла `lee.cor`, не входящего в обучение. При малом бюджете средняя точность была 58.68%; при 128 × 20000 — 97.36%. Это калибровочные примеры, использованные для выбора бюджета, а не независимая оценка всей атаки на автоматы.

Затем проведены 8 новых сквозных испытаний: фрагменты из других документов `lee.cor` зашифрованы известными нам нетривиальными автоматами из проверяемого семейства. Полный поиск без знания правильного автомата восстановил ≥90% букв в 4 случаях из 8; средняя точность — 69.68%.

Дополнительная диагностика подставила известный правильный автомат, оставив поиск букв прежним. Тогда во всех восьми случаях восстановилось более 95% букв; средняя точность — 98.42%. Это **диагностика с подсказанным ответом**, а не новая оценка слепого поиска.

В четырёх проваленных сквозных примерах правильная схема занимала на дешёвом предварительном этапе места 18, 32, 78 и 5 — и не попадала в тройку финалистов. Таким образом, найден конкретный источник ложных отрицательных результатов: ранний отбор слишком агрессивен.

Из-за этого нельзя вычеркнуть всё семейство автоматов по отсутствию убедительного результата на Dorabella. Следующий обоснованный эксперимент — улучшить отбор на известных контрольных шифрах, затем заново целиком повторить поиск и контрольную калибровку, не меняя правила по понравившимся фрагментам Dorabella.

## 8. Воспроизводимость и технические проверки

Сохранены исходная транскрипция, параметры языковой модели, случайные контрольные выборки, протокол поиска, 108 отдельных записей испытаний и все исходные программы. Никаких результатов на 99 контролях не экстраполировали из меньшего числа: все 99 вычислены.

Проверены обратимость 672 преобразований, 1000 вычислений изменения языкового балла по сравнению с полным пересчётом, детерминизм восьми параллельных повторов, повторный полный прогон Dorabella и соответствие итоговых счётчиков сохранённым контрольным массивам. Максимальная численная ошибка изменения балла: 4.67 × 10^−13. Подробности: `results/implementation_checks.json`.

Проверенная среда: Python 3.13.5; точные версии пакетов — `environment.json` и `requirements.txt`.

```bash
python -m venv .venv
# Активируйте виртуальное окружение способом, принятым в вашей ОС.
pip install -r requirements.txt
python audit.py --n 200000 --relabel-n 1000000
python automata.py
python language.py
python scan.py --controls 99 --positives 8 --workers 4
python diagnose.py
python checks.py
```

`scan.py` возобновляет работу из `results/scan_records.jsonl`. Чтобы пересчитать поиск с нуля, сначала сохраните копии результатов и удалите этот файл вместе с `results/scan_summary.json`. Программа откажется смешивать разные протоколы поиска. Параметр `--max-new 28` позволяет выполнять возобновляемые порции одного и того же эксперимента.

Языковая модель уже включена в архив; для повторного обучения удалите `data/english_model.npz`. Файл корпуса берётся из установленного пакета Gensim. Сам новостной корпус в архив не включён; его хеши сохранены.
