# TS-RC-v1 — статическая сверка оболочки до исполнения

Авторизация: прямое сообщение пользователя о подтверждении владельца 17.10.2026 11:42 UTC и требование одной попытки. Старый PLAN_MANIFEST.json со статусом ожидания разрешения не редактируется. Эта запись разрешает только runtime → model-load → один README87 control. Target/retry/resume запрещены.

Прочитан весь run_ts_rc.py без его импорта/исполнения; ast.parse подтвердил синтаксическую структуру. Повторно прочитаны закреплённый MCTS (540 строк) и пять его модулей. Проверены 12 исходных/архивных SHA256 и 10 системных SHA256; все совпали. Состояние /proc и памяти сохранено отдельно: прежнего attempt/root и соответствующих процессов нет. Это проверки чтением; Perl и контроль до freeze не запускались.

Авторский алгоритм/данные не изменены: mcts32–34 коэффициенты, 176 предел mi, 264 число детей в логах, 268–272 scoring, 275 hash-order, 428–439 две штатные половины, 487–534 injective Assume. При stderr даже с возможной последующей строкой результата — STOP. `date` (mcts63) остаётся единственной видимой в авторских файлах системной командой. Runtime probe не импортирует авторские модули.

Границы: AS и CPU — per-process; новая cgroup не создаётся. Сеть/другие файлы не запрещены ОС, но их обращения отсутствуют в прочитанном авторском коде; передаются только разрешённые argv/stdin. Общая cgroup может меняться из-за других задач. Timeout/кооперативные проверки не гарантируют realtime или завершение kernel I/O/host-crash; fsync не обещает долговечность после потери среды. Идентичность/чистота группы устанавливаются наблюдением для этого процесса, не отсутствием процесса в другой сессии. При остановке разрешено только дописать уже полученные свидетельства, не продолжать вычисления.

Статический вывод: оболочка реализует принятый ограниченный порядок без смены научного метода. Работоспособность Perl и вместимость моделей ещё не установлены; их должен показать ровно один разрешённый запуск. После любого исхода — review, без target.
