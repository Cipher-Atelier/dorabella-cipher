# Dorabella, round11: запуск и проверка

**Решения нет.** Здесь закончены 94 вычислительных входа нового ограниченного семейства. Старое отозванное «12/12 round11» не использовалось. Полный журнал: `dorabella_round11_research_log.md`.

## Размещение

Рабочая папка — `dorabella_lab`. Полный архив содержит неизменённые 7500 файлов round10 и каталог `round11`. Архив update содержит только `dorabella_lab/round11`: распакуйте его поверх **именно** `dorabella_lab_round10.zip` с SHA-256 `3dda3655d6322daafa13e455c0ea5b447e30748218bca2b532f594bf3ddd36af`. Ничего в старых раундах не перезаписывается.

Новая компактность не достигается удалением checkpoints: все основные 3760 checkpoints, 94 итоговых префиксных результата и 94 оценки продолжения включены. Для шести дополнительных полностью неотсечённых поисков включены хеши блоков и все максимумы/ничьи; сами огромные полные матрицы не включены. Они вычислялись, и `audit_exhaustive.py` восстанавливает их. Современный корпус/исходные полные исторические PDF заново не скачивались. Новые JIT-кеши и свободный lock-файл в ZIP не включаются; старые файлы архива, включая прежние кеши, сохраняются.

## Окружение

Python и точные установленные версии приведены в `environment.json` и `requirements_round11.txt`. Модель сохранена в `data/scoring.npz`; исходный словарь TextBlob проверяется по хешу. Выполняйте команды из `dorabella_lab`:

```bash
export OPENBLAS_NUM_THREADS=1
export NUMBA_NUM_THREADS=1
export PYTHONDONTWRITEBYTECODE=1
export NUMBA_CACHE_DIR="$PWD/round11/cache"
python -m pip install -r round11/requirements_round11.txt
```

## Проверить поставленные результаты

```bash
python round11/verify.py --kind all --sample-blocks --old-files
```

Это проверяет хеши, цепочки checkpoints, 80 553 сохранённые символьные оценки, отдельные независимые Python-словарные оценки, ключи, все обратные шифрования и контрольные последовательности. Оно не повторяет все 94 полных поиска.

## Гарантированно новый полный пересчёт

```bash
python round11/reproduce.py --case hauer_real --case hart_real
```

Каждый вызов создаёт **новую** папку `round11/audit/reproductions/fresh-*`, не принимает существующие итоги за повтор. На каждом входе заново рассматриваются все 30 965 760 ключей по первым 43 знакам; сравниваются все 40 массивных checkpoints. Эти новые папки не входят в зафиксированный основной манифест и не меняют научный протокол.

## Полное воспроизведение основной серии с сохранением старого расчёта

```bash
mv round11/checkpoints round11/checkpoints.delivered
mv round11/results round11/results.delivered
mkdir -p round11/checkpoints round11/results
python round11/run.py --kind positive,regression --workers 4
python round11/verify.py --kind positive,regression
python round11/run.py --kind real,null --workers 4
python round11/verify.py --kind all --sample-blocks --old-files
python round11/finalize.py
```

`run.py` возобновляет только незаконченные блоки и проверяет соответствие протокола; чужой активный runner защищён `fcntl`-блокировкой. При принудительном завершении незаписанный блок не засчитывается, законченные блоки сохраняются. В поставленном архиве все основные входы закончены; обычный повтор `run.py` использует кеш. Для нового пересчёта нужна команда `reproduce.py` либо отдельная папка, как выше.

## Полный независимый по отсечению аудит

```bash
mv round11/audit/unpruned round11/audit/unpruned.delivered
python round11/audit_exhaustive.py --workers 4
```

Для шести заранее указанных в `audit/unpruned_protocol.json` входов на **каждом** ключе вычисляются и C, и W, без верхних границ. Сравниваются глобальные максимумы и все точные ничьи. При остановке по лимиту инструмента сначала проверьте процессы; если runner уже завершён, повторите ту же команду, не удаляя checkpoints.

## Файлы, существенные для интерпретации

- `frozen_protocol.json`: неизменённый основной протокол и SHA-256 зависимостей.
- `data/search_inputs.json`: вход декодера, **только первые 43 знака**, без открытых текстов и ключей.
- `data/cases.json`: все 87 знаков, ответы положительных примеров, seeds и контрольные последовательности; не передаются функции поиска.
- `checkpoints/<id>/training_result.json`: выбранный только по префиксу ключ и все точные ничьи.
- `results/<id>.json`: отдельная последующая оценка последних 44 знаков и обратная проверка.
- `results/summary.json`: числа отчёта; `logs/commands.log` и остальные logs — реальные исполнения.
- `audit/ambiguity_diagnostic.json`: диагностика равных ключей **после** выбора; она не меняет результат по test.
- `audit/round10_file_hashes.json`: неизменность всех 7500 базовых файлов.

`cpu_work_seconds_sum` в тренировочных JSON — исторически неудачное имя поля: фактически это сумма измеренных `time.monotonic()` длительностей блоков (wall time), **не процессорное CPU-время**. Хешированная численная программа после заморозки не исправлялась ради переименования поля.
