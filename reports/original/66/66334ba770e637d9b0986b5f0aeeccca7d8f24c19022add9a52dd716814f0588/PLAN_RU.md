# TS-COMBINED-STORAGE-v1 — подготовленный единый gate, исполнения нет

## Одна интеграционная граница

Соединить два уже проверенных storage-компонента: исходный паттерн/word-membership API и LM prefetch. **Один Python broker, два изолированных pipe-канала**, неизменные Perl `CompactPatList.pm` и `Prefetch.pm`, исходные ReadLM/JMSmoothing/Utils/NoSpace. Нет переноса численной арифметики в Python. Общий клиент не нужен: раздельные FD сохраняют прежние независимые seq/buffers/close. Broker обслуживает готовые запросы последовательно через `select`; фоновых threads/jobs, очереди задач, сети и установок нет.

Подготовка не является разрешением исполнения. `T0=null`, attempt отсутствует. Единственная команда будущего согласования — `FREEZE.json:launch_shell_command`. Старые ZIP/attempts/научные T0 не изменяются. Полный solver entrypoint, P01, 87-control и Dorabella **запрещены** в этом пакете.

## Что сохранено и что изменено

Побайтно сохранены `Prefetch.pm`, `CompactPatList.pm`, `disk_contract.py`, `adapter.py`, `wire.py`, `namespace_view.py`, `process_guard.py`, original/*.pm. Source provenance и diff включены. У numerical harness изменены только подключение второго клиента, argc/FD и закрытие второго канала. MCTS/Selection/Expansion/Backpropagation/GetSuccessors/Insert/Assume и наблюдатели не изменены. Original commit: `2c7ad49cd4f4fa852168a8ce295bf739bf076adc`.

Сохраняются `-n` folding всех patlst orders в order1 без изменения исходного order1 словаря; последовательность/дубли списков, maxlen, fresh caller copies, исходный NoSpace. LM остаются raw strings, last duplicate wins, missing отсутствует; оригинальный Perl выполняет truth/unknown/backoff, multiplication/addition/log и округление. Ties — прежние strict comparison/order. Cache eviction меняет только IO: запрещены pruning/truncation, нормализация значений, fallback и retraining.

## Ровно одна будущая попытка

1. Launcher O_EXCL marker/T0, отказ при прежнем marker/attempt. Проверить runtime/code identities и PID/NSpid/starttime/argv; никаких сигналов чужим процессам. **До первого авторского процесса** нужен admission gate сразу всех LM, индексов, patlst и SQLite. При NO_GO — остановиться, не выполнять даже малую differential ради частичного результата. Все необходимые входы хешируются после admission; затем post-hash gate.
2. Reference Perl, затем combined broker + adapted Perl. Три прежних synthetic cases длины6, по2 MCTS-итерации; те же root keys, lambdas, x=.05, patternlimit50, UCB1, seed/env. Повтор имеет единственную интеграционную причину: теперь обе части storage работают одновременно, а ранее проверялись по отдельности. Нет отдельного rerun A2/A3/CH/52 или standalone adapter tests.
3. Сравнить **все320 событий** reference/adapted побайтно: scores/NV bits, ordered candidate traces, segmentation, keys, ties, unknown/missing/zero fixtures. Первые300 должны совпасть с прежним oracle; полный сохранённый oracle отличается только двумя абсолютными pathname в ожидаемых log(0) ошибках, замена локатора закреплена в readback. Прежние11 parser negatives остаются внутри этого неизменного edge harness, без отдельного этапа; новыми считаются не они, а composition/interleaving.
4. Только после exact PASS и свежего post-hash memory gate — **одна совместная real transport/integration проба** с тем же broker. Не real scoring: последовательно чередовать 8 patlst queries (`a,aa,ab,aba,abc,abcdefgh,!,abcdefgh`) и 9 прежних LM batches (36 +8×776). Полные 132856 candidate occurrences сравнить с сохранённым independent reference; повтор крупнейшего списка проверяет caller mutation isolation после межканальных запросов. Все6244 LM values/missing/last-row сверить с прежними36 intents/35 unique keys. Последний batch предваряется ровно6 сохранёнными NoSpace строками (`to,togo,xxyyzz,catdog,""," \t "`), проверить output и полный membership-query trace. Не выбирать новые строки или запросы по исходу. В phase реальных данных score/search calls=0.
5. Полные traces/stdout/stderr, commands, timings, limits, memory samples, input/output hashes, close двух каналов, normal exit0 и доказанно пустые собственные группы обязательны. Readback потоковый, без повторного scorer/solver. Отдельный внешний raw tool receipt и независимый saved-data readback нужны после попытки. На любом STOP/UNKNOWN — без исправлений, повторов и resume.

Успех всей попытки: `PASS_FINITE_COMBINED_STORAGE_ONLY`. Недопуск до авторского кода: `NO_GO_BEFORE_FOREIGN`. Новое давление после fixture: `PASS_COMBINED_FIXTURE_REAL_SKIPPED_RESOURCE` — **не полный gate**. Иные ошибки: STOP; недоказанное завершение: UNKNOWN. Даже полный PASS не является математическим доказательством всех численных исполнений, чувствительностью или разрешением 87-control.

## Время, процессная память и input pages

Общий180 с от T0, без reset. Начальная подготовка/hashes и fixture phase≤90 с; conditional real phase≤60 с и общий deadline. Каждая фаза оставляет4 с для TERM2/KILL2. Опрос50ms, кооперативные ticks; realtime hard-kill/host-crash durability не обещаются. Максимум3 процесса одновременно: supervisor и два ребёнка; всего не более5 child invocations. У каждого **AS64 MiB**, child CPU45/50 с, supervisor170/175 с, NOFILE64, CORE0, output≤8 MiB/file и32 MiB total. Исходные process-identity guards сохранены.

Real probe получает30 с от подключения клиентов до close обоих каналов; внутри неё суммарное измеренное время LM roundtrips/close≤10 с. Это **новое объединённое измерение**, не прежний standalone10-секундный wallclock benchmark: patlst/segmentation теперь чередуются с LM. Никаких обещаний throughput или cold-cache test. Реальные counters сохраняются, budget после результата не меняется.

Точная пофайловая сумма и состояние — `RESOURCE_BUDGET.json` и FREEZE. До hashes: `current + page-rounded(all pinned small/runtime files) +1MiB metadata + page-rounded(6 LM +6 indices +patlst +SQLite) +192MiB AS caps +64MiB IO/kernel/output allowance <7GiB`, при cgroup max=8GiB. После hashes и перед real: `current +192MiB+64MiB <7GiB`. Во время работы current≥7GiB либо новые OOM events →STOP. Резерв1GiB номинальный, не выделенный этой задаче. Ничего из cache/slab не вычитается; reclaim не предполагается. Не менять критерий ради PASS. При нынешнем недопуске freeze помечается **NO_GO**, с точным необходимым current ниже порога. Этот пакет не разрешает ждать/опрашивать память до случайного PASS.

## Совместные структуры и границы

- Patlst cache: максимум2 cached lists и8MiB учтённых Python objects; word cache1024 entries; SQLite `cache_size=-4096`, mmap0. 4MiB — настройка page cache, не hard bound всей SQLite. Один miss может временно держать старый cache, новый список, tuple и caller list; `adapter.py:46–100` не выдаёт8MiB за полный peak.
- Один полный candidate list≤63911 элементов, длина каждого≤46, raw payload≤2939906 B. Chunk64 сохраняет порядок/дубли. Broker и Perl каждый могут держать полную коллекцию; chunking ограничивает frame, а не всю модель кандидатов. В MCTS top50 применяется **после** чтения/сортировки списка — не bound его памяти.
- LM cache4096 entries на real dataset; key≤3×128 B +value≤96 B дают raw payload≤1966080 B; dict/tuples/ints/allocator дополнительно. В fixture только два cache по3. На одном score материализуются только необходимые U≤262/N≤514 записи исходными Perl-функциями; никаких полных LM hash.
- Два независимых request buffers≤65536 B каждый; replies LM≤128 values/chunk,≤7 chunks/batch, pat≤64 candidates/chunk,≤999 chunks/list +begin/end. Все кадры≤65536 B. Копии сериализации/parse и структуры Perl не объявляются равными raw payload. Pure-contract extremes: точные размеры в PREPARATION_RESULT. FD count≤64 на процесс, четыре однонаправленных IPC pipe между Perl/broker, без сетевых сокетов.
- **192MiB — сумма установленных AS limits, не измеренный resident peak**, и не охватывает kernel/cache/shared-соседей. 64MiB allowance — прежняя консервативная эксплуатационная оценка, не теорема kernel allocation. Совместный runtime peak пока неизвестен; превышение индивидуального cap означает STOP, не увеличение лимита. Нельзя суммировать отдельно испытанные RSS как доказательство совместного peak.

## Статическая подготовка и граница следующего решения

Разрешённый собственный preparation-test —37 заранее закреплённых pure byte/channel checks и AST12 Python files, 15 с/64MiB. Он не импортирует broker/adapter, не открывает модель, не вызывает IPC или Perl. Отрицательные случаи: cross-channel formats, неправильные seq/op/type, EOF, overflow/pipelining, close/partial/sequence caps. Это конечный тест контракта, не numerical equivalence. Perl не compile-check-ился; возможная syntax/runtime ошибка будет STOP единственной будущей попытки.

Если единый gate полностью пройдёт, следующая отдельная версия сможет подготовить ровно технический87-control с исходной frequency initialization и обоими storage APIs. Здесь нет такого entrypoint: остаются full-search peak/число кандидатов/стоимость NoSpace/throughput и чувствительность. Старый исходный control и его критерий нельзя считать уже выполненными. Не требуется ещё цепочка standalone microtests: один совместный finite gate предназначен для решения об этой интеграционной границе. Полный solver/target запрещены до отдельного необходимого согласования и обоснованного resource plan.

Для будущего согласования действие формулируется единым scope: **одна попытка combined fixture + условный real transport без поиска, до180 с, max3×AS64MiB, без сети/установок/личных данных, только по полным hashes и неизменному memory gate**. Пока NO_GO, не просить одобрить бессмысленный заведомо недопущенный запуск.
