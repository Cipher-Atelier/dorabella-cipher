# Проверенный индекс .patlst: контракт чтения

Этот документ описывает формат; исполняемый solver сюда не добавлен. База пригодна только вместе с точными исходными байтами `.patlst`. Перед использованием требуется проверить оба SHA256:

- `attempt/patlst_index.sqlite`: `c35f28462555da9982ed975b713a291b654a0e2b0d514e7d498f717bdf386070`, 537591808 байт.
- `model/lmtrain_nyt_word.patlst`: `2849bc03f85c59a422f1945960ce04a4b6e66cc02c61a6484de0283c30c724fd`, 340083717 байт.

Открывать SQLite в `mode=ro`, не выполнять VACUUM, удаление таблиц или переписывание схемы. Поле source_path в metadata сохраняет исходный путь создания, а не удостоверяет новый путь после распаковки; реальный источник разрешается только по хешу. Параметры pattern/word передаются как bytes/BLOB, не как TEXT с иной collation.

`segments`: seq INTEGER PRIMARY KEY (исходные 1-based строки), original_order, pattern BLOB (после исходного удаления пробелов), offset (0-based байты), raw_bytes, count, longest. `by_pattern` — индекс `(pattern,seq)`. Точная последовательность сегментов для p:

```sql
SELECT seq, original_order, pattern, offset, raw_bytes, count, longest
FROM segments WHERE pattern=? ORDER BY seq;
```

Для каждого сегмента читать ровно raw_bytes по offset из проверенного файла, нормализовать как parser_a в закреплённом runner и выдавать кандидатов в исходном порядке. Нельзя сортировать, дедуплицировать, пропускать исходные orders2/3 или применять pl заранее. Равенство всех сырых строк и полных списков двух парсеров уже проверено на всех7548932 строках. Глобальное объединение равняется последовательной конкатенации этих сегментов; порядок SQL-запроса обязателен.

`words(word BLOB PRIMARY KEY)` — множество123619 слов, только из исходного order1 после удаления пробелов. `words_oracle` — сохранённое независимое контрольное множество; равенство проверено в обе стороны. Не включать в словарь все фразы из orders2/3. `metadata.maxlen = 46` — максимум по всем нормализованным кандидатам, как у исходного ReadPList при -n.

Полное покрытие:7548932 строки;10662322 кандидата с кратностями;5927556 нормализованных pattern;290257 pattern объединяют разные исходные orders. Максимальный список одного pattern —63911 элементов. Дисковый индекс не обязан быть меньше текстового источника: он устраняет необходимость держать все Perl-объекты одновременно в RAM.

Фактическая проверка: raw bytes по index-offset совпали с отдельным последовательным reader; все полные списки совпали с независимым парсером; count/maxlen/словари/seq проверены; source SHA256 и SQLite quick_check совпали; normal exit0,118.649034191с. Второй внешний readback проверил receipt и sealed SHA256 без повторного разбора модели.

Это не гарантирует эквивалентность будущего Perl/Python adapter. Ещё не проверены оригинальное исполнение, численные преобразования и score, ties/hash-order/траектория, скорость lookup, рабочая память поиска, сегментация в исполняемом Perl и87/87 на истинных контролях/target.
