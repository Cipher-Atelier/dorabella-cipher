# CH3-v1 — статическая сверка до единственного запуска

Порт не импортировался и не исполнялся при этой проверке. Проверены синтаксис AST, разрешённые импорты и фактическое тело кода.

| Оригинал Lyons | Порт и принятое отличие |
|---|---|
| ngram_score.py 10–19 | LyonsModel: те же счётчики, N, log10(float(count)/N), floor log10(0.01/N); только замена Python 2 API, проверка входного файла и кооперативные проверки срока |
| ngram_score.py 21–28 | score: 84 слагаемых слева направо, dict.get вместо эквивалентного membership/getitem; никаких W/слов/весов |
| break_simplesub.py 17–23 | Вместо бесконечного цикла — пять отдельных стартов из A–Z, как требует CH3; точный SHA256 seed, shuffle |
| break_simplesub.py 24–36 | Два randrange(26), включая a=b; swap; только строгое улучшение; reset count=0 затем count+=1; 1000 или 5000 предложений |
| pycipher | Явная class→letter подстановка; это принятый порт, не побитовый повтор исходного encryption-key API |
| CH3: четыре ветки | groups_for: (5,15), (22,8), сортировка по min, одиночные остальные 0…23; фиксированные фазы; structural до поиска |
| Контроли | prepare_controls: принятые E/T и возрастающие свободные глифы, отсутствие замены; q[i]=p[2i mod87]; полные inverse до model/search |
| Независимость процедуры | encoder использует счётчики; inverse_record отдельно считает появления в префиксе. Обе реализации всё же используют одну таблицу циклов; это не независимое историческое свидетельство |
| Истина и поиск | run_branch не получает plaintext/key/назначение правильной ветки. Истина отдельно на диске, повторно читается postsearch только после всех 40 веток |
| Время/работа | До каждого предложения проверка 4/180; 1 млн максимум, ≤200 начальных score и ≤4 true score. T0 до hash/runtime/model/control prep. Сохранение после лимита разрешено без новой поисковой работы |
| Остановка | attempt.mkdir(exist_ok=False), нет resume/retry; любой inverse mismatch→STOP_ERROR; global deadline→STOP_GLOBAL_TIME. Файлы текущих максимумов сохраняются по каждому старту |

При статическом review исключён platform.platform(): некоторые реализации Python могут получать processor через дочернюю команду. Использован только os.uname(). Это исправлено ДО первого запуска. Никаких контрольных математических тестов или пробного поиска здесь не было.

Кооперативные лимиты не гарантируют hard kill или запись после host crash. При исчезновении процесса без terminal/exit исход unknown; отсутствие процесса не считается успехом. При обычном завершении нужен observed exit 0, terminal, хеши и полный учёт.
