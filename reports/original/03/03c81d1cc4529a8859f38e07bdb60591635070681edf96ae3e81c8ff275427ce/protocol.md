# BE-W16-v1: один перспективный bounded-поиск

**Статус: SPECIFICATION_ONLY, не executable freeze и не разрешение запуска.** Это новый детерминированный pattern-guided поиск с ограниченными Expansion; не исходный MCTS, не EAGER, не новая криптосемья. Цель одного пилота — проверить, удаётся ли полное blind-восстановление свежих 87-буквенных подстановок при доступном бюджете. Никаких Dorabella, Lincoln, RFC или P01 в пилоте.

## 1. Неизменные научные компоненты

Обычная инъективная моноалфавитная подстановка a–z, естественный порядок, 87 позиций. Исходные canonical Pattern, frequency initialization и Assume из pinned HHK commit `2c7ad49cd4f4fa852168a8ce295bf739bf076adc`; `PERL_HASH_SEED=2026101705`, `PERL_PERTURB_KEYS=0`, никаких новых стартов/подбора seed. @C и исходный начальный ключ сохраняются буквально. Неиспользованные plaintext-буквы разрешены; inverse определяется на встречающихся символах, а полный 26-буквенный ключ достраивается только канонически: оставшиеся cipher/clear буквы попарно в ASCII-порядке.

Сохраняется также явная таблица original cipher→canonical Pattern symbol. Ключ поиска компонуется с ней: inverse проверяется против исходных 87 cipher symbols, не только против внутреннего Pattern. Scored/visited проверяется наличием ключа в отдельном множестве, не truth численного score; конечный score 0 сам по себе не ошибка.

Неизменны исходные NoSpace/maxlen46/order-1 dictionary и **арифметика оригинального Perl JMSmoothing**: char λ=(.0950848948641174,.229797965264228,.675117139871655), word λ=(.129793302623898,.226872659329747,.643334038046355), x=.05. Unknown, Perl truth, backoff, порядок операций и raw numerical strings прежние; никаких новых языковых признаков или обучения. NoSpace SHA256 `6c6f0bc2173a3ae5170f658d36a1b2ab4d31571c41d9e5a10159cc40550c6188`; JMSmoothing `74b033a6899f33be4e70243fe645863252aa379e13739242b7d3fef9c8867357`; Utils `8708e8db3c182004ccb3e3d57d9ed205882ab923a81bf007df27877ab4177b2e`. Все 14 модельных идентичностей — прежний `model_inputs.json`, SHA256 `ef691ac69cb2a0a5f66b08b11bb024ec16093d6d4b8d0131e50e9758090c5aab`. Индексы не перестраиваются.

## 2. Точный поиск и смысл покрытия

Один initial state, сначала его полная сегментация/score. Затем ровно восемь bounded Expansion r=0…7; никаких restart, polish, reheating или переноса бюджета.

1. Заморозить текущий ключ K на всю Expansion. Обойти **все 3870 исходных окон-слотов** `(s,l)`, s=0…85, l=2…46, лексикографически. Сохраняется исходная семантика substr с усечением у конца: повторяющиеся усечённые окна не исчезают. Их pattern зависит только от cipher, не от гипотезы plaintext.
2. Для каждого окна взять исходный ordered patlst со всеми дублями. Пусть L=min(50, число элементов). При L=0 записать empty. Иначе выбрать **единственный** 0-based индекс `j=floor((2r+1)*L/16)`. Это заранее фиксированные восемь квантилей исходных первых 50, а не первые восемь или лучший по target. Никакой similarity-sort. Identity proposal и уже scored key записываются как пропуски; другой кандидат вместо них не берётся. Для остальных применить исходный Assume к K. Инъективность обязательна.
3. Отнести окно к одной из 16 клеток: start-bin=floor(4s/86), length-bin=[2..4], [5..8], [9..16], [17..46], по **запрошенной** l. В каждой клетке выбрать предложение с минимальным `(SHA256(ASCII("BE-W16-v1|window|r|s|l|j")),s,l,j)`; числа без ведущих нулей, разделитель `|`. Hash — фиксированный порядок покрытия, не случайная выборка и не оптимизируемый seed. Истина, score и буквы предложенного plaintext в этот порядок не входят.
4. Если один key выбран несколькими клетками, оставить наименьший номер клетки, без дозаполнения. Сегментировать и score не более 16 выбранных строк, в порядке клеток. Сохранять каждую полную строку, key, segmentation, score bits и 87-позиционный inverse. Полная unspaced строка задаёт уникальность решения; разные сегментации/ключи не умножают один ответ.
5. После **завершённой** Expansion следующий current — её лучший ранее не scored key, даже если он хуже current; visited/scored ключи не возвращаются. Ties: numeric score, затем ASCII unspaced plaintext, затем key. Best-so-far хранится отдельно; все distinct строки с равным максимальным numeric score сохраняются. Пустая Expansion сохраняет K и увеличивает r: следующий квантиль может дать другой ход. На частичной Expansion state transition не совершается; уже полученный best помечается partial.

Покрытие означает, что каждое окно участвует в формировании предложений на каждом завершённом раунде. **Это не scoring каждого окна/кандидата**: на scoring идут представители 16 пространственно-длиновых клеток. Журнал обязан различать рассмотрено, предложено, выбрано, scored. Полного покрытия всех ключей нет. Изменены candidate subset, dynamics и ties; вероятное пропускание истины — проверяемое ограничение метода, а не повод расширять выбор после результата. В отличие от прежнего CH3/tabu/SA здесь ходы — словарные pattern-assumptions по всем окнам и опубликованная combined LM, а не swaps с Lyons quadgrams.

Для каждого тела: убрать только напечатанное обращение, затем оставить ASCII A–Z/a–z, lowercase, взять первые 87. ## 4. Новый перспективный бюджет и устранение per-word IPC

Одинаково для всех восьми входов: **129 scores максимум** (root+8×16), 8 Expansion, 180 s от case-start, work cutoff130 s; max3 процесса, AS supervisor/broker/Perl=128/128/256 MiB. Восемь случаев последовательно: **1440 s для случаев + отдельные 60 s общей подготовки = 1500 s (25 минут) максимум**, не прежние 180 s на всю серию. Порядок P1,N1,P2,N2,P3,N3,P4,N4 задаётся supervisor; decoder не получает эти метки. Никакого заимствования неиспользованного времени. Один запуск каждого; нет resume/retry. Это новый бюджет, не поправка к v3.

Общий T0 предшествует gates/проверкам/fixtures; общая подготовка входит в отдельные 60 s и не отнимается только у первого positive. Превышение этого срока = STOP_PREPARATION, без поисков. Затем у каждого случая собственные одинаковые 180/130 s, включая fresh gates и загрузку; кеши поиска/подстрок/pattern/LM холодные, межслучайного reuse нет. Системный page cache не очищается и может создавать различия времени; одинаковый допуск не означает одинаковый фактический workload. При непрохождении общего integration gate поиски не начинаются. Незапущенные случаи отражаются отдельно, их бюджет не переходит другим. Meta/close/handshake имеют отдельный предел 16 сообщений на случай сверх указанных ниже content requests; raw frames учитываются независимо.

Чтобы не повторить v3, перед каждой NoSpace передать broker все её непустые подстроки: не более 3828 в порядке `(start,length)`; значения order-1 membership загружаются пакетами≤128. Broker возвращает только exact presence; Perl FETCH читает полученную таблицу и возвращает прежние 1/undef. Любой незагруженный ключ — STOP, не silent fallback. Каждый логический FETCH считается, включая повтор и false. Это изменение storage/glue, **ещё не реализованное и не проверенное**; не перенос NoSpace или численной LM в Python. Все рекурсивные аргументы NoSpace — подстроки исходной строки, поэтому таблица покрывает их, в том числе whole-string lookup >46.

Полная последовательность key/value восстанавливается из строки, каталога и references; счётчики/cap проверяются отдельно. LM requests/raw values/score bits сохраняются полностью. Общие caps могут завершить случай раньше; для результатов нельзя молча исключить evidence или считать отсутствующие записи PASS.

Конечность и перечисленные counts доказуемы из конструкции. **Завершение за 180 s, скорость batch lookup, heap peak и exact equivalence нового glue не доказаны.** Именно они проверяются в одном будущем ограниченном пилоте; недостаток времени — не отрицательное свидетельство о plaintext. Нет обещания recovery из 129 evaluations.

## 5. Приёмка и одно окончательное решение

Один общий prospective executable freeze должен включать эту спецификацию, control data, source/diff hashes и независимый data verifier. В том же конечном запуске перед поисками — только необходимые integration assertions: prefix50→восемь квантилей совпадают по order/duplicates с immutable source; bulk presence true/false/absent и logical order эквивалентны исходному membership на фиксированных малых fixtures; оригинальный NoSpace/JMSmoothing дают точные segmentation/score bits на них. Это не отдельная серия калибровки. Любое расхождение = STOP_CORRECTNESS, никакой подстройки или продолжения к search.

Каждый control проходит полный обратный encoder для каждого scored candidate, все 87 позиций, с инъективным ключом. Это проверка механизма, **не recovery**. Exact recovery засчитывается только если единственный максимальный **87-буквенный** plaintext равен отложенной истине. Истина среди tied maxima — неоднозначность, не успех gate. При NaN/Inf, нарушении ключа/inverse, mismatched input/source — STOP_CORRECTNESS. Срок/счётчик/AS/output = INCOMPLETE_BUDGET; незавершённый раунд и partial best сохраняются отдельно. Неопределённый exit/cleanup/evidence = UNKNOWN. Неудачные входы остаются в знаменателе 4.

**GO только к рассмотрению одного B0 target pilot:** все восемь случаев завершили свои восемь раундов и evidence/cleanup проверки; ≥3/4 positives имеют уникальное exact recovery; в каждой из четырёх пар найденный positive maximum строго выше negative maximum, без допуска и без исключения ties. Последнее — заранее заданный descriptive discrimination gate, **не p-value, не оценка false-positive probability и не «0/4 ложных расшифровок»**. Все остальные исходы = NO_GO этой версии, без tuning на этих же controls. Любые subsequent target candidates требуют независимых доводов; high score/87-roundtrip недостаточны. Калибровка обычной подстановки не переносится автоматически на CH1 B1–B3 или зависимые транскрипции.

Приёмка новых результатов: первичный tool stdout вычисленных hashes → закрытые неизменяемые файлы → seal (без последующих append) → ZIP → exact Library readback → независимое сравнение всех terminal/counters/raw frames. Исторические STOP остаются. Новый test не объясняет прежнюю потерю журнала.

**Решение сейчас:** научная спецификация определена; можно рассматривать один такой пилот, но запускать ещё нечего. Минимальные незакрытые условия — материализовать уже фиксированные четыре источниковых capture и keys без отбора, проверить их отсутствие в прежних controls, реализовать и статически закрепить единственный new selection/transition + bulk-membership glue. Без этих данных/кода и exact integration evidence объявлять executable-ready нельзя. Новые algorithm/scorer trials сегодня не выполнялись; никакого EAGER-пакета не создавалось.
